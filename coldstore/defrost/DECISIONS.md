# 化霜流程定稿

本文件对化霜流程里悬而未决的问题给出定论，代码实现与本文件一致。

## 1. 结霜量判定：温差积分，时长只做兜底

**定论：以温差积分为主判据，时长作为安全兜底。**

结霜量 `frost_load` 按房间空气温度与蒸发盘管温度的温差，在**冷风机运行期间**对时间积分：

```
frost_load += max(room_temp - coil_temp, 0) × Δt      （仅风机运行时累计）
```

理由：

- 霜是湿空气流过冷盘管时凝结形成的，霜质量正比于“风机运行时长 × 温差”，积分与霜质量相关；
- 纯时长估计把停机、空载、常温闲置都算成结霜，必然误判；
- 风机停机时积分不增长，符合物理事实。

兜底规则：自上次化霜完成（或首次探温）起经过 `max_interval` 秒，即使积分一直不到阈值
（探头故障或长期零温差），也强制触发。判定结论里 `reason` 明确区分触发来源：

| reason     | 含义                                   |
| ---------- | -------------------------------------- |
| `load`     | 积分达到 `frost:load-threshold`        |
| `interval` | 超过 `frost:max-interval` 的兜底触发   |
| `manual`   | 操作员强制启动                         |
| `none`     | 未到触发条件                           |

化霜正常完成后积分清零，并重新计时。

## 2. 一次化到底还是分段化：一次化到底

**定论：单次化霜（single stage），一次化到盘管达到结束温度，再经过滴水停留期结束。**

不做分段化霜。分段加热之间盘管会重新结冻，既浪费能量，又让“化没化完”变成模糊状态。
单段流程的结束判据是“盘管温度达到结束温度 + 最短滴水停留时间”双条件；
加热另有最大时长保护，超时即异常中止并回滚。

## 3. 状态机与回滚点

```
started ──> stopping_fans ──> fans_stopped ──> heating ──> draining ──> completed
                │                  │              │           │
                └──────────────────┴──────────────┴───────────┴──> aborted（回滚）
```

- `started`：**先判定触发**，通过后抓取回滚点（当时在运行的风机、主风机、时间戳），再停风机；
- `fans_stopped`：必须显式确认所有风机已停稳，才允许进入加热；确认时发现风机仍在转，
  记录 `fan_stop_failed` 事件并拒绝加热（可重试确认或中止）；
- `heating`：逐次上报盘管温度；达到结束温度进入 `draining`；超过最大加热时长自动中止；
- `draining`：滴水停留满 `drain_seconds` 后才能完成；
- `completed`：恢复回滚点记录的风机、清零结霜积分、房间退出化霜态；
- `aborted`：任何非终态都可中止，**按回滚点恢复风机**，房间退出化霜态。
  中途取消不再留下半截状态。

## 4. 留痕台账（不可修改）

所有流程事件只追加到 `defrost:ledger`，状态由事件流折叠得到：

`started / fan_stopped / fan_stop_failed / heat_began / heat_sample / drain_began /
completed / aborted`（另有 `fan_restore_skipped` 记录回滚时无法恢复的风机）

- 事件带顺序号 `seq`、会话号 `session_id`、库房号、时间戳、明细与载荷；
- 回滚点随 `started` 事件落盘，每次状态迁移与回滚动作都在台账中留痕；
- 会话一旦进入 `completed` / `aborted`，再追加任何事件直接拒绝
  （`LedgerError`），因此**化霜记录一旦形成不可修改**，系统也不提供任何编辑/删除端点；
- 底层 Store 写入是临时文件 + 原子替换，崩溃不会产生半截台账。

## 5. 重放一致性

- 命令队列按库房去重；
- `replay` 对同一持久化台账是幂等的：库房已有进行中会话则**续跑**（`resumed`），
  不存在才新开（`started`），拒绝重复升温；
- 会话到达终态后其命令才从队列移除；
- 重启控制台时，内存中的“化霜中”标志从台账重建；`recover` 会把遗留的进行中会话
  逐个中止并回滚风机，再清空队列——终态记录原样保留。

## 6. 查阅端点

- `GET /defrost/trajectory?id=<库房号>`：该库房**每一次**化霜的完整轨迹
  （每个状态、每个温度采样、回滚点、终态与原因）；台账是持久化的，即使库房
  尚未在内存注册，历史轨迹仍可查；
- `GET /defrost`：队列、进行中会话、完成/中止计数；
- `GET /defrost/trigger?id=<库房号>`：当前结霜判定结论；
- `GET /frost` / `POST /frost/observe`：积分状态与探温喂数。

## 7. 端点与操作序列

| 端点 | 作用 |
| ---- | ---- |
| `POST /defrost/start` `{id, force?}` | 判定触发，抓回滚点，停风机（未到触发条件且未 force 时拒绝） |
| `POST /defrost/confirm-fans` `{id}` | 确认风机已停稳；仍有风机在转则留痕并拒绝 |
| `POST /defrost/heat` `{id}` | 确认停稳后才开始升温；此时风机仍转将自动中止并回滚 |
| `POST /defrost/heat-sample` `{id, temp}` | 加热中盘管采样；到结束温度进滴水，超最大加热时长自动中止 |
| `POST /defrost/finish` `{id}` | 滴水停留结束后完成并恢复风机；停留不足拒绝 |
| `POST /defrost/abort` `{id, reason?}` | 任意非终态中止并回滚到上一个稳定态 |
| `POST /defrost/enqueue` / `POST /defrost/replay` | 命令队列与幂等重放 |
| `POST /defrost/recover` | 中止遗留会话、回滚风机、清队列、按台账重建标志 |
| `GET/POST /defrost/config` | 结束温度、最大加热时长、滴水停留时长 |
